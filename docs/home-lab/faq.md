# 常见问题

[文档首页](../readme.md) · [部署](deployment.md) · [使用](usage.md)

## 另一台设备没有更新

网站表单保存是预览，还要 **保存到云端**。确认使用同一个站点与 KV，另一台设备刷新。正常浏览模式中的主题选择和配色保存会独立写入共享配置；登录页/已登录页面在可见期间分别每 15/30 秒检查，重新聚焦也会刷新。编辑或弹窗期间不会覆盖草稿，KV 跨地区传播可能额外延迟。布局等其他本地偏好不保证同步。

## 为什么主分支叫 master？

本仓库沿用了 Dashy 上游的默认分支名称。`master` 与 `main` 都是分支名，本项目使用 `master` 汇总确认的改动，`feat/…`、`fix/…` 用于试验和修复。单独新建 `main` 不会自动切换默认分支或 Cloudflare 的生产分支；如需改名，应连同构建触发、PR 目标和保护规则一起调整。

## GitHub 已合并，为什么网站还是旧版本？

合并只说明代码已进入主分支。继续查看 Cloudflare Workers Builds 是否收到该 SHA、构建是否通过、部署是否成功、生产域名是否指向相同 Worker。确认后再刷新页面，启用 PWA 时也检查新版本提示。没有构建日志和线上验证，不能仅凭 PR 的 Merged 状态判断已上线。

## 能补回过去的 Git 记录吗？

已存在的提交可通过 [历史索引](history.md) 查阅。本索引按真实 GitHub 提交补写中文说明，不改作者、时间或 SHA。只有最终文件而没有当时快照的改动，不能准确拆成过去的提交；应在今天新增如实的补记。域名、Secret 和 KV 内容属于运行配置，不会自动成为 Git 提交，维护时须分别记录与备份。

## 图标变成首字母

这是获取失败的占位。读取按钮支持当前路径、相对地址和 PWA 清单；仍失败可能是登录、访问限制、动态图标或无有效声明。可选择图库或手动图片，不要填含 Token 的 URL。

## 新网站能自动生成英文说明吗？

当前没有统一自动摘要功能。说明字段可填写简洁、准确的一句英文，已有网站可单独整理。

## HTTP 与 Ping 有两个状态点

两者独立：HTTP 检查网页响应，Ping 检查主机 ICMP。可以只开一项。Ping 需要后端，未接入时显示提示；呼吸动画不代表每一帧都发请求。

## 工作台拒绝打开网站

目标可能用 CSP/X-Frame-Options 禁止 iframe，改为新标签页。Home Lab 不绕过目标策略。

## 天气失败或与手机不同

检查 `OPENWEATHER_API_KEY`、城市/坐标和接口授权。数据商、地点与更新时间不同会有差异；一位小数只改变显示精度，不提高天气源准确度。

## 公开仓库会暴露我的配置吗？

源码与 KV 分开，代码部署不会自动把线上配置提交到 GitHub。但上传私人 YAML、Cookie、密钥或未脱敏截图会暴露内容。分享前先脱敏，Secrets 不写进仓库。

## 可以直接按上游 Docker 文档部署吗？

本 fork 主要目标是 Worker + 静态资源。先用本项目部署指南；上游文档用于字段与组件参考，不能把上游镜像等同于当前 fork。

## 合并上游怎样保留 UI？

对比分离功能、接口与界面定制，再合并并验证三视图、布局、尺寸、保存和密钥边界。先导出备份，不用整个上游目录覆盖 fork。
