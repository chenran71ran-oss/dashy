# 启动速度与内存

分支 `claude/perf-startup-memory-fable`，基线为 `master` 03a55de。数字来自本地 Worker + 生产构建，在无缓存的 Chromium 中打开总站页测得；体积为未压缩字节数。本机没有网络延迟，线上的时间差异会比这里更明显，但未在线上测量。

| 项目 | 之前 | 之后 |
| --- | ---: | ---: |
| 首屏加载的脚本 | 1541 KB | 685 KB |
| Logo 图片 `/mech/blue.png` | 739 KB | 54 KB |
| 默认主题的三个拉丁字体 | 577 KB（TTF） | 237 KB（WOFF2） |
| 启动时的配置与会话请求 | 3 次（`/api/session`、`/conf.yml` ×2） | 1 次（`/conf.yml`） |
| 卡片出现后的 JS 堆 | 18.2 MB | 10.0 MB |
| 出现第一张卡片（本机，冷启动） | 613 ms | 约 475 ms |

## 改动

- **图标目录按需加载**：卡片只需要「图标名 → 文件」的对应关系，却在启动时加载了带标题、标签、分类的完整目录（550 KB）。现在启动时只加载 33 KB 的索引（`scripts/build-icon-index.mjs` 生成），完整目录在打开图标库时才下载。`:rocket:` 这类短代码表情的对照表（64 KB）也改为用到时加载。
- **Logo 图片**：机甲标识原图为 1254×1254，实际显示不超过 128px。缩小为 256×256。
- **启动请求合并**：原来先请求 `/api/session` 确认登录，再下载应用代码，再请求配置，另有 Service Worker 检查重复请求一次配置。现在第一次请求直接取配置（401 即未登录），结果交给 store 使用；登录过的浏览器同时并行下载应用代码。未登录的访客仍然只加载登录页。
- **配置对话框按需加载**：配置对话框带着 YAML 解析器和 schema 校验器（ajv），原来随首屏加载，现在打开时才下载。云端配置是 JSON，YAML 解析器只在返回 YAML 文本时加载。
- **字体**：Raleway、Inconsolata、PT Mono 由 TTF 转为 WOFF2（字形不变），并设置 `font-display: swap`。1.1 MB 的中文字体只在系统没有中文字体时下载：字体族中 PingFang SC、Microsoft YaHei 在前，另为 Android、Linux 增加了系统 Noto Sans CJK 等本地字体名。
- **图标库内存**：图标选择器里的三千多个 simple-icons 条目只构建一次并冻结，由所有选择器共享，不再为每个选择器各建一份响应式副本。

## 内存

- **30 秒轮询不再重建页面**：已登录页面每 30 秒读取一次配置，原来无论是否变化都会重置 store 并重新渲染所有卡片。现在配置文本没变就直接跳过。
- **泄漏检查**：在浏览器中强制垃圾回收后测量。专注视图切换分类 32 轮，DOM 节点数（1001）和事件监听器数（433）不变，堆从 6.20 MB 到 6.59 MB。总站、专注、工作台之间切换 22 轮（66 次路由切换），节点数（2248）和监听器数（951）不变，堆从 8.49 MB 到 9.48 MB。堆仍有少量增长，未查明来源；节点和监听器没有累积。

## 限制

- 第一次访问或清除站点数据后，浏览器没有登录标记，应用代码不会提前下载，这一次与之前一样是顺序加载。
- 时间数字是本机单次测量，不代表线上各种网络下的表现。
